# 项目拆解

## 目标

把任何开源项目变成一份"看完就能上手"的中文学习指南，文档化后直接提交进项目仓库，方便自己和社区学习。适用于 GitHub 仓库、获奖项目、个人重点项目。

## 输入

- 必需：仓库名（owner/repo）或在线地址。
- 可选：关注重点（产品 / 架构 / 学习路线）、输出语言、是否提交回仓库。

## 工作流

### 1. 取证（先读透再动笔，一切事实来自仓库）

用 GitHub API 拉取：

```bash
# README 与文档目录
curl -s -H "Authorization: Bearer $TOKEN" https://api.github.com/repos/<owner>/<repo>/readme
curl -s -H "Authorization: Bearer $TOKEN" \
  https://api.github.com/repos/<owner>/<repo>/contents/docs
# 顶层目录结构
curl -s -H "Authorization: Bearer $TOKEN" \
  https://api.github.com/repos/<owner>/<repo>/contents/
# 关键源码目录（stores / core / types / content 等）
```

逐份阅读核心文档（architecture.md / product-overview.md / north-star.md / story-bible 等），记录真实信息：获奖情况（README 或官方站点）、功能列表、技术栈、目录职责、核心模块。

若项目有在线预览，先访问确认可用并记录 URL；预览不可访问时如实标注，不写"可访问"。

### 2. 学习指南模板（Markdown）

```markdown
# 🕵️ <项目名> 学习指南

> 一句话宣传语（引用官方原文）

## 🏆 项目名片        ← 名称/获奖/预览/一句话定位/核心情绪
## 💡 核心产品创意     ← 解决什么问题 / 产品回答 / 核心循环流程
## 🎮 核心玩法/机制    ← 分阶段表格：玩家做什么 vs 系统做什么
## 🏗️ 代码架构        ← 架构图(文本/ASCII) + 关键模块表 + 目录速览
## 🛠️ 技术栈          ← 表格：技术 → 用途
## 📚 学习路线建议     ← 从"先体验 → 读产品 → 读架构 → 读代码 → 看决策"的序号步骤
## 💬 一句话总结
```

### 3. 写作规则

- **架构图用文本/ASCII 或表格**，不依赖图片也能看懂依赖关系。
- **关键模块表**：模块 → 位置（真实路径）→ 职责，路径必须与仓库一致。
- **目录速览用树形**（```text``` 代码块），只标注有意义的关键目录，不罗列全部。
- **学习路线强调"先玩后读、由外到内"**，每一步指到具体文件路径。
- **客观边界**：写"当前实现"，不把规划/愿景写成已实现功能；不确定处标注。
- **保留原文引用**：核心定位、宣传语等用官方原文并标注出处。

### 4. 提交与验证

- 指南文件命名：`<PROJECT>_LEARNING_GUIDE.md`，放仓库根目录或 docs/。
- 用 Contents API PUT 提交（先 GET 拿 sha）。
- 浏览器打开 GitHub 预览页验证：表格、链接、代码块渲染正常。

## 检查清单

- [ ] 所有事实（获奖/功能/路径/技术栈）来自仓库实测
- [ ] 核心循环用流程说明白，架构有可视化表达
- [ ] 学习路线每一步可执行（有具体文件路径）
- [ ] 在线预览链接已验证可访问（或如实标注不可访问）
- [ ] 推送到仓库并浏览器验证渲染
