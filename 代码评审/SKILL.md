# 代码评审

## 目标

输出结构化的评审结论：按严重程度分级（阻断 / 建议 / 可选），每条给出问题位置、原因与可执行的修改示例。

## 核心流程

### 1. 先建立上下文

- 读代码前先看：项目 README、package.json / requirements.txt / go.mod、目录结构、`.gitignore`。
- 明确语言与技术栈、是否框架项目（React/Next/FastAPI 等）、数据流方向。
- 如果是 PR：先看 diff 整体，再聚焦改动文件，理解"这个改动想解决什么"。

### 2. 按五维度审查

| 维度 | 检查点 |
|---|---|
| 正确性 | 边界条件、空值、并发、状态变更、异步错误处理、浮点/时间精度 |
| 安全 | OWASP Top 10：注入（命令/SQL/XSS）、路径穿越、密钥硬编码、不安全的反序列化、CSRF |
| 性能 | 不必要循环、N+1 查询、大对象内存、未索引字段、重复计算 |
| 可读性 | 命名、函数长度、魔法数字、注释质量、重复代码（DRY） |
| 架构一致性 | 分层是否清晰、是否引入反模式、依赖方向、与现有模式是否一致 |

### 3. 输出格式

```markdown
## 评审结论
**整体评价**：✔️ 可合并 / ⚠️ 需修改 / ❌ 必须重写

### 🔴 阻断级（必须修复）
- 位置：`src/xxx.py:42`
  问题：...
  示例：...

### 🟡 建议级（强烈建议）
- ...

### 🟢 可选级（锦上添花）
- ...

## 总结
（一段话概括代码质量与最大风险点）
```

### 4. 安全红线（重点）

- 发现密钥/令牌硬编码 → 阻断级，提示立即轮换密钥并改用环境变量/密钥管理。
- 发现拼接 SQL / eval / exec / shell 拼接 → 阻断级，给参数化写法。
- 发现用户输入未转义进入 HTML/URL → 阻断级，提示转义或白名单校验。

## 检查清单

- [ ] 每条结论都有文件:行号定位
- [ ] 修改建议是可直接执行的代码示例，不是空话
- [ ] 区分了"确定问题"与"潜在风险"
- [ ] 安全维度至少过一遍注入/密钥/越权
- [ ] 最终给出整体评价与合并建议
