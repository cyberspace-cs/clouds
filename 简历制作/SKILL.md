# 简历制作

## 目标

输出一份可直接部署上线的个人简历/作品集网页：身份鲜明、项目可点、技能可读，适合面试官 3 分钟浏览。交付形态：单页 HTML 或 Vite+React 工程，可发布到 GitHub Pages。

## 输入

- 必需：姓名、身份定位（如"LLM Agent Engineer"）、技术栈。
- 项目素材：每个项目要拿到 名称 / 一句话定位 / 技术栈 / 关键成果 / 演示链接或仓库链接。没有链接的项目不写占位链接，标注"本地/私有"。
- 可选：经历时间线、教育、证书、开源贡献、获奖（重点突出）。

## 工作流

### 1. 收集素材（先问全再动手）

- 按上表一次性向用户收集；缺项标注"待补充"，不编造。
- 项目数量、成果数字必须来自用户提供材料。
- 获奖信息重点标注（黑客松 / 竞赛 / 开源奖项）。

### 2. 页面结构（信息密度优先）

```text
Hero 区：名字 + 定位 + 核心关键词 + 联系方式按钮
About 区：2-3 句自我介绍（突出差异化）
Projects 区：项目卡片网格（定位/技术栈/成果/链接）
Skills 区：按类别分组的技能矩阵（文字 + 熟练度，不用图标墙）
Timeline 区：经历时间线（可选）
Footer 区：GitHub / 邮箱 / 社交链接
```

**设计要点**：
- 深色或浅色任选，保持一致性；避免大面积紫色（除非用户指定品牌色）。
- 项目卡片包含：项目名、定位一句话、技术栈标签、2-3 条成果（量化优先）、Demo/源码链接。
- 移动端优先：单列布局，触控目标 ≥ 44px。
- 响应式：桌面网格 ≥2 列，移动端单列。

### 3. 实现方式选择

| 场景 | 方案 |
|---|---|
| 快速交付、单文件 | 单页 HTML（内联 CSS/JS），可直接双击打开 |
| 需要工程化 | Vite + React + TS，`npm create vite@latest` 起项目 |
| 已有工程 | 在现有代码上改，不重建 |

- 部署时结合"页面上线" skill 走 GitHub Pages 流程（`--base=/<repo>/`）。
- 单页 HTML 内联资源路径用相对路径，避免子路径 404。

### 4. 内容真实性校验

- 逐条验证链接可访问；404 的链接移除或标注。
- 禁止编造项目成果、公司经历、证书。
- 数字（star、用户量、准确率）必须来自用户或可验证来源。

## 检查清单

- [ ] 页面在手机与桌面宽度都可用
- [ ] 每个项目卡片信息完整（定位/技术栈/成果/链接）
- [ ] 无失效链接、无编造数据
- [ ] 浏览器实际打开渲染正常
- [ ] 已部署或给出可部署的仓库
